# AI 綜合應用觀察規範

## 定位

依指定期間內可讀取的本機 Codex 工作紀錄，產生個人化且可追溯的 AI 應用觀察。這不是完整工作績效、人格評價或跨員工比較，不得用 Token、次數、時間或單一分數直接下結論。

## 分析順序

1. 先整理量化資料：Token 結構、工作紀錄數、使用／適用天數、活躍互動估計、跨週持續性、專案群組、工作分類及 Skill 覆蓋率。
2. 再逐筆閱讀納入的工作 Session，確認任務目的、處理方式、查核行為、實際成果及限制。
3. 依六個固定面向建立內部評估與證據。
4. 選擇一至兩項最明確優勢及一項有證據支持的改善方向。
5. 產生 `90–160` 個中文字的自然語言觀察；資料不足時允許較短，但必須明確限制結論強度。
6. 在詢問同仁自評前先完成觀察，且不得因自評分數修改 AI 的獨立結論。

## 六個固定面向

1. `使用投入與持續性`：使用頻率、活躍比例、跨週持續性，以及是否逐步融入實際工作。
2. `任務廣度`：涵蓋的專案群組、產品線、工作分類、Skill、工具及工作流程。
3. `任務深度與複雜度`：多步推理、跨資料比對、反覆修正、除錯、驗證及結論收斂程度。
4. `成果與實務價值`：是否形成可採用的分析、設計審查、程式、文件、報告、工作簿、簡報、交換檔或決策。
5. `品質、查核與風險意識`：是否要求來源、證據、測試、Build、Review、交叉比對及風險辨識。
6. `可複用性與成熟度`：是否形成 Script、Skill、Template、Workbook、標準流程或其他可重用成果。

每個面向只允許內部使用 `1–5` 或 `N/A`。數字評分必須附簡短 evidence；資料不足使用 `N/A`，不得解讀為低價值。

## 成熟度

- `資料不足`：可讀紀錄不足，無法形成可靠結論。
- `起步探索`：已有工作使用，但頻率、深度或成果仍在累積。
- `穩定應用`：能持續用於實際工作並形成明確成果。
- `成熟應用`：廣度、深度、驗證及成果價值均有穩定證據。
- `高度整合`：AI 已廣泛融入流程，並持續形成高價值或可複用成果。

成熟度不得只由 Token、活躍時間、工作紀錄數或六項平均分自動決定。`internalScore` 可省略；如使用，只供內部一致性檢查，不顯示於 PPT、不排名，且證據不足時不得產生。

## 個人化評語

評語依序包含：整體使用特徵、主要任務或深度、實際成果、成熟度判斷及一項改善方向。至少使用兩種不同類型的證據，且改善方向必須對應實際缺口。

不得：

- 使用固定罐頭句只替換姓名或數字。
- 因 Token 高就給高評價，或因 Token 低就給低評價。
- 虛構成果、ROI、節省時數或效率百分比。
- 描述人格、態度、忠誠度、智力或無法由工作紀錄證明的能力。
- 比較其他同仁、使用名次、百分位或團隊平均。
- 把本期 AI 應用觀察冒充完整年度績效。

    ],
    "strengths": ["有證據支持的主要優勢"],

`status` 只能是 `evaluated` 或 `insufficient-data`；`dimensionAssessments` 恰好包含六個固定面向，不得缺少、重複或增加。工作紀錄為 `0` 時固定使用 `insufficient-data`、`資料不足`，六項分數皆為 `N/A`。
